# Supernote Tools decisions

The history of consequential decisions. Each current rule lives where the last column says; this
page is the only home of decision history.

| 2026-11-13 | Ink2Pic becomes lasso-only, dropping last-word recognition; a separate image-edit plugin is future work; sticker-vs-image is to be tested on the device | last-word recognition; one plugin doing search and editing | [`issue #32`](https://github.com/martonpaulo/supernote-tools/issues/32), [`ROADMAP.md`](../ROADMAP.md) |
| 2026-11-14 | Layered architecture: feature logic is pure and provider-agnostic; external services sit behind provider interfaces (Todoist, Google, iCloud/CalDAV, ICS, dictionary/translation), and all Supernote internals live behind one `sn-adapter` whose authorities/columns/rules are an updatable descriptor with an adapt-on/off probe that disables a module on a device mismatch. Nothing hardcodes a Supernote internal or a single service in feature code. Every plugin's features are opt in/out in its own Settings | hardcoding providers and device internals in each plugin | [`architecture.md`](architecture.md) |
| 2026-11-14 | Plugin and tool names: plugins `bridge` (to-do+calendar+digest, settings-only, no note surface), `lookup` (picture+definition, merges ink2pic and the planned ink2def), `lingo` (translation; language pairs opt in/out), `retouch` (image edit), `probe` (on-device investigation); host tools `snadb` (the ADB CLI) and `desk` (macOS `.note` editor). Repo stays `supernote-tools`. Shared packages `sn-adapter`, `sync-core`, `ink-core` | the `calendar-bridge`/`todo-bridge`/`digest-bridge` split and a `supernote-sync` bundle | [`architecture.md`](architecture.md) |
| 2026-11-14 | Sync is **one** plugin (`bridge`) with to-do/calendar/digest as opt-in/out modules, not separate plugins and not a bundle superplugin | separate standalone sync plugins plus an optional `supernote-sync` bundle (old [#40](https://github.com/martonpaulo/supernote-tools/issues/40)) | [`architecture.md`](architecture.md), supersedes [`issue #40`](https://github.com/martonpaulo/supernote-tools/issues/40) |
| 2026-11-14 | A plugin can open a TCP listener and receive a connection from the Mac over Wi-Fi, with the screen on and with it off (Probe dev.4 on the owner's tablet: `listen accept OK` both rounds), so `relay` receives over LocalSend inside the plugin ([#91](https://github.com/martonpaulo/supernote-tools/issues/91), [#49](https://github.com/martonpaulo/supernote-tools/issues/49)) | a receiver through ADB or a synced folder | [`plugin-scope.md`](plugin-scope.md) |
| 2026-11-14 | Bridge, Ink2Pic and Lingo share the Settings look through one package, `packages/ui-kit` (tokens, shared styles, `Button`), that Metro bundles into each plugin (owner decision D17 A, [#93](https://github.com/martonpaulo/supernote-tools/issues/93)) | Ink2Pic's own `src/ui/metrics.ts`, `styles.ts` and `Button.tsx`; Bridge's literals | [`packages/README.md`](../packages/README.md), [`architecture.md`](architecture.md#the-plugins-on-device) |
| 2026-11-15 | Turning a Bridge module or provider off keeps every row Bridge wrote; a module that is off offers one «Remove what Bridge wrote» button, confirmed once more, that removes only Bridge's rows: calendar `tag=task` rows and To-Do tasks imported from the service (owner D15 A, [#89](https://github.com/martonpaulo/supernote-tools/issues/89)) | no rule: a disabled calendar's rows stayed with no owner | [`architecture.md`](architecture.md#the-plugins-on-device) |

| 2026-11-15 | `lookup` is a new plugin with its own `pluginID` beside Ink2Pic, not Ink2Pic renamed; the owner does not use Ink2Pic day to day, so its settings and picture library need not carry over (owner D40 B, [#110](https://github.com/martonpaulo/supernote-tools/issues/110)) | the recommendation to rename Ink2Pic in place | [`plugin-scope.md`](plugin-scope.md#lookup) |
